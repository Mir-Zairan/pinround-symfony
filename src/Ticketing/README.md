# Ticketing

Tickets from the first report to done: keys, moves, assignment, lead checks and duplicate links. It owns the tables `tkt_project`, `tkt_ticket`, `tkt_ticket_event`, `tkt_duplicate_link` and `tkt_summary`. Its Api is `ProjectQueries`, `ProjectSummary`, `ProjectChoice` and `ProjectPermission` (built), `TicketQueries` and `TicketCommands` (still to come), plus its public events. It may use the Api of Workflow, Organization, Media and Insight. Its Domain has the `Ticket` aggregate (mapped to `tkt_ticket`; `Ticket::report` starts a ticket in To do with an assignee, else in Backlog), `TicketKey`, `TicketType`, `Priority` and `Visibility`; `tkt_summary` has no entity yet. It implements Workflow's `StepOccupancy` (`Infrastructure\Workflow\TicketStepOccupancy`), so Workflow learns how many open tickets are in a step without calling Ticketing; it returns 0 until P03 adds tickets. The Team page's project actions are its POST routes `ticketing_team_projects_unlink`, `ticketing_team_projects_link` and `ticketing_team_projects_create` under `/teams/{slug}/projects` (`UI\TeamProjectsController`); each runs in a transaction of its own through SharedKernel's port `Application\Transactions`.
