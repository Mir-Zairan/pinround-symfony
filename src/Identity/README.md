# Identity

Users and how they sign in: invites, passwords, two-factor login, Microsoft login and API tokens. It owns the tables `idn_user`, `idn_credential`, `idn_password_reset`, `idn_mfa_secret`, `idn_sso_identity`, `idn_api_token` and `idn_login_attempt`. Sessions live in Valkey. Its Api is `CurrentUser` (built: the logged-in user of the request or of a security token, `Infrastructure\Security\SymfonyCurrentUser`), `UserQueries` (built: `idByEmail`, `Infrastructure\Doctrine\DbalUserQueries`), `LoginAssurance` (built: whether a security token is a password session, only the form login's `UsernamePasswordToken` is, and whether its two-step login is confirmed, never until P01.T6; `Infrastructure\Security\SymfonyLoginAssurance`), `TokenAuthenticator` and `ApiTokens`. Two-step login setup is built (P01.T6 step 1): `/me/security/two-step` turns it on with a QR code drawn on the server, a code from the app and 10 recovery codes shown once (`StartTwoStepSetup`, `ConfirmTwoStepSetup`, entity `TwoStepLogin` on `idn_mfa_secret`). Login step two is built (P01.T6 step 2): for a user with two-step login on, the right password only starts a pending login (`PendingLogin`, `Infrastructure\Security\SymfonyPendingLogin`, started by the listener `AskForTwoStepCode`), and `/login/code` (`LoginCodeController`) takes a code from the app or one recovery code (`AcceptTwoStepCode`) and finishes the login; every login records its times per user in the session (`SessionConfirmations`). "Confirm it's you" is built (P01.T6 step 5): an action marked with SharedKernel's `RequiresRecentAuth` opens only after the password and a code in this session within 10 minutes (`RecentAuth`); the UI listener `AskToConfirmItsYou` sends anyone else to `/me/confirm` (`ConfirmItsYouController`, `ConfirmItsYou`), or, while two-step login is off, to its setup page. Turning it off and the admin gate come next. It may use the Api of SharedKernel only.
