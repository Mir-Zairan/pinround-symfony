# Identity

Users and how they sign in: invites, passwords, two-factor login, Microsoft login and API tokens. It owns the tables `idn_user`, `idn_credential`, `idn_password_reset`, `idn_mfa_secret`, `idn_sso_identity`, `idn_api_token` and `idn_login_attempt`. Sessions live in Valkey. Its Api is `CurrentUser` (built: the logged-in user of the request or of a security token, `Infrastructure\Security\SymfonyCurrentUser`), `UserQueries` (built: `idByEmail`, `Infrastructure\Doctrine\DbalUserQueries`), `InvitedPersonRegistration` (built: creates an active user and its password for the invite accept page in the caller's transaction, or throws `RegistrationRefused` listing `RegistrationRefusal` cases before any write; `Application\RegisterInvitedPerson`), `LoginAssurance` (built: whether a security token is a password session, only the form login's `UsernamePasswordToken` is, whether its user has two-step login on, and whether they typed a code in this session within N seconds and not before it was last turned on; `Infrastructure\Security\SymfonyLoginAssurance`, through `RecentAuth`), `TwoStepProofPages` (built: the paths of "Confirm it's you" and of the setup page with the way back, for Organization's admin gate; `UI\Controller\RecentAuthRedirects`), `TokenAuthenticator` and `ApiTokens`. Two-step login setup is built (P01.T6 step 1): `/me/security/two-step` turns it on with a QR code drawn on the server, a code from the app and 10 recovery codes shown once (`StartTwoStepSetup`, `ConfirmTwoStepSetup`, entity `TwoStepLogin` on `idn_mfa_secret`). Login step two is built (P01.T6 step 2): for a user with two-step login on, the right password only starts a pending login (`PendingLogin`, `Infrastructure\Security\SymfonyPendingLogin`, started by the listener `AskForTwoStepCode`), and `/login/code` (`LoginCodeController`) takes a code from the app or one recovery code (`AcceptTwoStepCode`) and finishes the login; every login records its times per user in the session (`SessionConfirmations`). "Confirm it's you" is built (P01.T6 step 5): an action marked with SharedKernel's `RequiresRecentAuth` opens only after the password and a code in this session within 10 minutes (`RecentAuth`); the UI listener `AskToConfirmItsYou` sends anyone else to `/me/confirm` (`ConfirmItsYouController`, `ConfirmItsYou`), or, while two-step login is off, to its setup page. Turning it off is built (P01.T6 step 4): `/me/security` asks for the password and a code (`SecurityPageController`, `DisableTwoStepLogin`), deletes the `idn_mfa_secret` row and removes the session's proofs. The admin gate is built (P01.T6 steps 3 and 6): admin pages need two-step login on and a code of the last hour in this session, checked by Organization's `AdminAreaVoter` through `LoginAssurance`; a code proof counts for admin pages and `RequiresRecentAuth` only while two-step login is on and only from the second it was last turned on. It may use the Api of SharedKernel only.
