# Identity

Users and how they sign in: invites, passwords, two-factor login, Microsoft login and API tokens. It owns the tables `idn_user`, `idn_credential`, `idn_password_reset`, `idn_mfa_secret`, `idn_sso_identity`, `idn_api_token` and `idn_login_attempt`. Sessions live in Valkey. Its Api is `CurrentUser` (built: the logged-in user of the request or of a security token, `Infrastructure\Security\SymfonyCurrentUser`), `CurrentTimeZone` (built: the logged-in user's saved time zone, UTC when nobody is logged in or none is saved; `Infrastructure\Security\SymfonyCurrentTimeZone`), `UserQueries` (built: `idByEmail`, and `byIds`, which gives each known user's `UserView` (id, display name, first name) in one query and does not limit users to the tenant, as they are global; `Infrastructure\Doctrine\DbalUserQueries`), `InvitedPersonRegistration` (built: creates an active user and its password for the invite accept page in the caller's transaction, or throws `RegistrationRefused` listing `RegistrationRefusal` cases before any write, or EmailTaken alone with the EntityManager closed when another transaction took the email at the same moment; `isValidEmail` says whether an address passes the account email rule, so InviteMember refuses what accepting would; `Application\RegisterInvitedPerson`), `LoginAssurance` (built: whether a security token is a password session, only the form login's `UsernamePasswordToken` is, whether its user has two-step login on, and whether they typed a code in this session within N seconds and not before it was last turned on; `Infrastructure\Security\SymfonyLoginAssurance`, through `RecentAuth`), `TwoStepProofPages` (built: the paths of "Confirm it's you" and of the setup page with the way back, for Organization's admin gate; `UI\Controller\RecentAuthRedirects`), `LoginAssurance::isTokenAuthenticated` (built, P09.T1: whether a security token is the `ApiTokenAuthentication` a personal access token login creates) and `CurrentApiToken` (built, P09.T1: `access()` gives the request's `ApiTokenAccess`, the token id, its organization and its scope names, null for a browser session or nobody logged in; `Infrastructure\Security\SymfonyCurrentApiToken`). `Infrastructure\Security\TokenAuthenticator` (built, P09.T1, not an Api) authenticates the stateless `api_token` firewall of `/mcp` and `/api/v1` by the `Authorization: Bearer pr_…` header alone: a live token makes the request its user's with the token's organization as tenant and records its use at most once a minute; anything else gets the same 401 and leaves no tenant. `UI\Voter\AdminNeedsBrowserSessionVoter` denies a token actor every `ADMIN_*` attribute and `ORG_ADMIN` and `ORG_INVITE`, and `OwnAccountVoter` denies it `ACCOUNT_EDIT_OWN` (ADR-0021). Personal access tokens are stored (P09.T1): `Application\IssueApiToken` issues one and returns `IssuedApiToken`, whose plain token is shown once; it refuses a 21st token that still works per person and organization with `TooManyApiTokens`, counting under a per-person advisory lock in the caller's transaction. `ApiTokens` (`DoctrineApiTokens`) is the module's own repository, not an Api; the hash is HMAC-SHA256 keyed by `API_TOKEN_PEPPER` (`HmacApiTokenHashing`, ADR-0043). Two-step login setup is built (P01.T6 step 1): `/me/security/two-step` turns it on with a QR code drawn on the server, a code from the app and 10 recovery codes shown once (`StartTwoStepSetup`, `ConfirmTwoStepSetup`, entity `TwoStepLogin` on `idn_mfa_secret`). Login step two is built (P01.T6 step 2): for a user with two-step login on, the right password only starts a pending login (`PendingLogin`, `Infrastructure\Security\SymfonyPendingLogin`, started by the listener `AskForTwoStepCode`), and `/login/code` (`LoginCodeController`) takes a code from the app or one recovery code (`AcceptTwoStepCode`) and finishes the login; every login records its times per user in the session (`SessionConfirmations`). "Confirm it's you" is built (P01.T6 step 5): an action marked with SharedKernel's `RequiresRecentAuth` opens only after the password and a code in this session within 10 minutes (`RecentAuth`); the UI listener `AskToConfirmItsYou` sends anyone else to `/me/confirm` (`ConfirmItsYouController`, `ConfirmItsYou`), or, while two-step login is off, to its setup page. Turning it off is built (P01.T6 step 4): `/me/security` asks for the password and a code (`SecurityPageController`, `DisableTwoStepLogin`), deletes the `idn_mfa_secret` row and removes the session's proofs. The admin gate is built (P01.T6 steps 3 and 6): admin pages need two-step login on and a code of the last hour in this session, checked by Organization's `AdminAreaVoter` through `LoginAssurance`; a code proof counts for admin pages and `RequiresRecentAuth` only while two-step login is on and only from the second it was last turned on. A new display name saved by `UpdateProfile` publishes `Api\Event\UserRenamed` on event.bus through `Application\IdentityEvents` (`Infrastructure\Messenger\MessengerIdentityEvents`); it is an `Api\Event\IdentityEvent`, which goes to the outbox in the change's transaction and on to `async_notify`, so Organization clears its team people cache only once the relay and worker-notify have handled it, and the old name can show until then. It may use the Api of SharedKernel only.
