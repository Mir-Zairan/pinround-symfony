# Web

The UI shell: layout, navigation built from the user's roles, Home composition and the design-system Twig components. It has no business logic and only puts other modules' UI pieces together. It owns one table, `web_home_focus` (each user's Home focus chip per organization), and has no Api of its own. It may use the Api of Insight, Organization, Notification, Ticketing and Workflow (read only). `UI\Controller\TeamController` serves the team page `GET /teams/{slug}` (`team_show`): 404 for a slug no team of the request's organization has, then `TEAM_VIEW`; it reads the team (`TeamQueries::bySlug`) and its projects (`ProjectQueries::projectsOf` for the `CurrentActor`, one query plus one batch of the open ticket counts that viewer may see) and shows the projects, a People shell and a line under the title: for the lead "You lead this team. You link its projects and add its own steps.", for an admin who is not the lead "Only the team lead can remove projects and change steps.", for anyone else "Only the team lead can change projects and steps." "See tickets" links to `ticketing_tickets?project=KEY` once that route exists (`UI\Team\ProjectTicketsLink`). For the lead it adds "Remove" on each project, and for the lead or an admin an "Add project" dialog (link projects that have no team, create a new one) that posts to the `Ticketing\UI\TeamProjectsController` routes; `assets/controllers/project-picker_controller.js` filters its list. Below the projects it shows "How work moves here": the policy sentence (`SettingsQueries::stepPolicyOf`), the five groups with the team's steps (`StepQueries::moveTargetsFor`, so none of the team's own steps under `locked`), team steps highlighted with a `×` for whoever has `STEP_CHANGE_TEAM`, an "Add a team step" panel for the same people, and the three rules (`RuleQueries::rulesFor`) as switches for whoever has `RULES_CHANGE_TEAM`, else as On/Off marks "set by the team lead" under `team` and "set by the admin" otherwise; the forms post to the `Workflow\UI\TeamWorkflowController` routes, whose names, token ids and labels `TeamController::WORKFLOW_FORMS` copies.

The admin shell (P14.T3, extended by P11): `UI\Controller\Admin\AdminShellController` serves `GET /admin` (`web_admin`, `MainMenu::ADMIN_ROUTE`), which asks Organization's `ADMIN_AREA` and redirects to the first tab `UI\Admin\AdminTabRail` gives the person. The rail lists each tab by label, route name (a string, so Web reads no module's UI) and the attributes its page asks, in the prototype's order, and Twig `admin_tabs()` gives it to `@Web/admin/layout.html.twig`, which every tab's template extends from the module that owns the tab (Organization's People and AI today). `AdminTabRail::isAdminAreaRoute` tells `MainMenu` when the Admin item is current. A non-Admin's refused `ADMIN_AREA` becomes a 404 in Organization's `HideAdminAreaFromNonAdmins`.

My reports (P14.T15, P07.T6): `UI\Controller\MyReportsController` serves `GET /my-reports` (`my_reports`, `MainMenu::MY_REPORTS_ROUTE`) after `OrganizationPermission::VIEW`. It reads one page of the person's reports (Insight's `HomeQueries::myReports`, 50 newest first, one query) and sorts that page into Needs you, Stuck and Moving, with Done folded, by Insight's `GroupedReports`; "Show more" carries the keyset cursor as `?after=<Unix seconds>.<ticket id>` (`UI\MyReports\MyReportsCursorParameter`), and any other value is a 404. Each report is a card from `UI\MyReports\ReportCards` (one batch of turn people's names and the cached steps, built with the same time as the groups): key and title link, side text (bold in the waiting colour when Stuck), `UI\Component\ProgressDots` over `ReportStage::labels()` with the text "Step 2 of 4: Building", the turn person's avatar, the Now line (`ReportCardText`) and Answer (with a hidden " on KEY") only on Needs you. The intro line is Insight's `MyReportsCounts::totalsOf` over all pages (one query, none for an empty page); the menu's count tag is `MyReportsCounts::questionsWaitingOn` (one query). An empty first page offers Report a problem. Styles: `assets/styles/my-reports.css`, `.progress-dots` in `components.css`.
