# Insight

Read models for Home and manager views: whose turn it is, team counts and release progress. Home reads ready rows and never scans tickets. It owns the tables `ins_ticket_turn`, `ins_project_counts`, `ins_project_count_ticket`, `ins_team_counts` and `ins_release_progress`. Its Api is `TurnProjector::refresh(TicketId)`, which rewrites one ticket's turn row in the caller's transaction from the facts of the `TicketTurnSource` port, moves the ticket's project count with the same facts (`DbalProjectCountsProjector`), and returns the turn's override note, `TurnProjector::refreshFrom(TicketTurnSnapshot, ?array $waitingTurns = null)`, the same write from the ticket's facts its caller has already read (SharedKernel's `TicketTurnSnapshot`, through the port's `factsFrom`), so a change such as the move does not read the ticket again; `$waitingTurns` is the team's waiting reviews and tests read in the same transaction, or null to read them (3 queries warm on an open ticket whose count stays with none given, 2 with them), `TurnUserQueries::turnUsersOf(list<TicketId>)`, the turn users of the tickets list's shown rows in one query on `ins_ticket_turn` (no visibility filter: the caller passes only ids the viewer may see), `ProjectCountQueries::countsOfTeam(TeamId, UserId, bool)`, the project rail's open and done counts for one viewer (a team-only ticket counts for its own team's people and admins, anyone else counts only tickets for everyone), `TeamLoadQueries::waitingTurnsOf(list<UserId>, TicketId)`, the reviews and tests waiting for each person (the loads of the turn facts, shared with `DbalTicketTurnSource`), `TeamLoadQueries::loadsAndSavedTurnOf(list<UserId>, TicketId)`, the same loads together with the ticket's own saved turn in one query (for the ticket page), `WaitingTurnCounts::waitingCountsOf(TicketViewer, list<UserId>, ?TeamId, ?string $projectId)`, how many open tickets wait on each person and since when, in one query (none for no person): every turn kind counts, only tickets the viewer may see, and every asked person is returned (0 and null when nothing waits on them); `TicketViewer` is the viewer's visibility as SharedKernel values, which the caller fills from Ticketing's `TicketVisibility`, and `HomeQueries::whoseTurn(TicketViewer, ?string $projectId, ?string $openedGroup, ?TurnGroupCursor $after, ?string $searchText = null): WhoseTurnPage`, the Whose turn view's groups by person or label in one query, narrowed by a search to the tickets list's best 1,000 matches (`isTicketCountCapped` past them) (5 tickets each and 100 for the opened group; counts, oldest waits and rows only of tickets the viewer may see), joining `ins_ticket_turn` to Ticketing's view `tkt_ticket_list_v`. A `WhoseTurnPage` holds `groups` (the viewer's own first, on the first page only, then at most `HomeQueries::GROUPS_PER_PAGE`, 20, others, by the oldest wait), `ticketCount` (every ticket the viewer may see, on the page or not) and `nextCursor`, a `TurnGroupCursor` (the last group's oldest wait and user id or label) or null on the last page; `$after` goes on after a cursor by keyset on (oldest wait, label or not, user id or label byte by byte), never by offset, and leaves out the viewer's own group. It may use the Api of Workflow and Ticketing.

`HomeQueries::myReports(TicketViewer, ?MyReportsCursor): MyReportsPage` reads one page of the tickets the viewer reported, open and done (`MY_REPORTS_PER_PAGE`, 50, newest first by keyset on created time and id, one query). `DbalMyReportsRows` reads Ticketing's view `tkt_ticket_list_v` (its `reporter_id`, `created_at`, `closed_at` and visibility columns), left-joined to `ins_ticket_turn` by primary key, so a done ticket with no turn row is listed too; the ticket visibility predicate runs on the view's own columns, and a reporter always passes it, team-only reports included. `DbalMyReportsRowsTest` proves the filter, the order with ties, and 300 reports walked 50 at a time with no gap or repeat. The Api's `GroupedReports::of(list<MyReport>, now)` sorts a page into `ReportGroup` Needs you, Stuck (no change for more than 7 days), Moving and Done, with how many each shows before "Show N more", in pure code for the page that shows them. `MyReportsCounts` (`DbalMyReportsCounts`) gives the menu's badge (`questionsWaitingOn`: the reporter's open reports with a question to them, one query on `ins_ticket_turn`) and the intro line's `MyReportsTotals` (`totalsOf`: every report the viewer may see and the ones that need their answer, one query); `DbalMyReportsCountsTest` proves the filters and row-level security.
