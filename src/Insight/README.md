# Insight

Read models for Home and manager views: whose turn it is, team counts and release progress. Home reads ready rows and never scans tickets. It owns the tables `ins_ticket_turn`, `ins_project_counts`, `ins_project_count_ticket`, `ins_team_counts` and `ins_release_progress`. Its Api is `TurnProjector::refresh(TicketId)`, which rewrites one ticket's turn row in the caller's transaction from the facts of the `TicketTurnSource` port, moves the ticket's project count with the same facts (`DbalProjectCountsProjector`), and returns the turn's override note, `TurnProjector::refreshFrom(TicketTurnSnapshot, ?array $waitingTurns = null)`, the same write from the ticket's facts its caller has already read (SharedKernel's `TicketTurnSnapshot`, through the port's `factsFrom`), so a change such as the move does not read the ticket again; `$waitingTurns` is the team's waiting reviews and tests read in the same transaction, or null to read them (3 queries warm on an open ticket whose count stays with none given, 2 with them), `TurnUserQueries::turnUsersOf(list<TicketId>)`, the turn users of the tickets list's shown rows in one query on `ins_ticket_turn` (no visibility filter: the caller passes only ids the viewer may see), `ProjectCountQueries::countsOfTeam(TeamId, UserId, bool)`, the project rail's open and done counts for one viewer (a team-only ticket counts for its own team's people and admins, anyone else counts only tickets for everyone), `TeamLoadQueries::waitingTurnsOf(list<UserId>, TicketId)`, the reviews and tests waiting for each person (the loads of the turn facts, shared with `DbalTicketTurnSource`), `TeamLoadQueries::loadsAndSavedTurnOf(list<UserId>, TicketId)`, the same loads together with the ticket's own saved turn in one query (for the ticket page), and `HomeQueries`. It may use the Api of Workflow and Ticketing.
