# Insight

Read models for Home and manager views: whose turn it is, team counts and release progress. Home reads ready rows and never scans tickets. It owns the tables `ins_ticket_turn`, `ins_project_counts`, `ins_project_count_ticket`, `ins_team_counts` and `ins_release_progress`. Its Api is `TurnProjector::refresh(TicketId)`, which rewrites one ticket's turn row in the caller's transaction from the facts of the `TicketTurnSource` port, moves the ticket's project count with the same facts (`DbalProjectCountsProjector`), and returns the turn's override note, `TurnUserQueries::turnUsersOf(list<TicketId>)`, the turn users of the tickets list's shown rows in one query on `ins_ticket_turn` (no visibility filter: the caller passes only ids the viewer may see), `ProjectCountQueries::countsOfTeam(TeamId, UserId, bool)`, the project rail's open and done counts for one viewer (a team-only ticket counts for its own team's people and admins, anyone else counts only tickets for everyone), and `HomeQueries`. It may use the Api of Workflow and Ticketing.
