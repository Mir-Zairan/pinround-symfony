# Organization

Organizations, teams, members, roles, invitations and settings such as ping limits and AI policy. It owns the tables `org_organization`, `org_membership`, `org_team`, `org_team_member`, `org_invitation` and `org_settings`. Its Api is `MembershipQueries`, `CurrentActor`, `TeamQueries`, `OrgSettings` and the voter attributes `OrganizationPermission`, `TeamPermission` and `AdminPermission`, and its events in `Api\Event` (`MemberJoined`, `OrgRolesChanged`, `TeamCreated`, `TeamRoleChanged`, all `OrganizationEvent`), which go through the outbox to `async_notify`. `MembershipQueries::rolesOf` gives one user's `Roles` in an organization (`isAdmin`, `isManager`, `isLeadOf`, `isMemberOf` and `isViewerOf` for exactly that team role, `isInTeam` for any, `teamIds`; `Roles::none()` without a membership); `DbalMembershipQueries` reads it under row-level security with no cache, so it needs an open transaction under that organization as tenant and finds nothing otherwise. `TeamQueries::teamsOf` gives that organization's team ids and `summariesOf` the id and name of the asked ones, ordered by name, `allSummariesOf` those of every team in one query and `countOf` how many there are; `DbalTeamQueries` reads all four the same way. `CurrentActor::actorFor` gives a voter the `ActorContext` (user id, organization id, `Roles`) of the token user it is given in the request's tenant, or null without either; `Infrastructure\Security\RequestScopedCurrentActor` builds it once per request for each user and organization and the kernel resets it between requests, so role changes take effect at the next request. Its commands in `Application` (`CreateOrganization`, `AddMember`, `SetOrgRoles`, `CreateTeam`, `SetTeamRole`) write in the caller's transaction and publish their events through `OrganizationEvents` (`Infrastructure\Messenger\MessengerOrganizationEvents`). SetOrgRoles locks the organization's admins and SetTeamRole the team before changing anything, so concurrent changes keep an admin and one lead. Built so far in `UI`: `EnterChosenOrganization` sets each web request's tenant from the organization chosen in the session, checked against `MembershipQueries::organizationsOf` (`resolve_user_orgs`), and `/org/choose` (`OrganizationChoiceController`, checked by `OrganizationMemberVoter`) lets a user choose or switch. `UI\Voter\OrganizationVoter` decides `ORG_VIEW` (the organization the request works in, which EnterChosenOrganization sets only for a member) and `ORG_ADMIN` (an Admin there); `UI\Voter\TeamVoter` decides `TEAM_VIEW` (any team role in the team, or Admin or Manager of its organization) and `TEAM_LEAD` (only the team's Lead), reading the organization's teams at most once per request; `UI\Voter\AdminAreaVoter` decides `ADMIN_AREA` (an Admin of the request's organization with a password session, two-step login on and a code typed in this session within the last hour, `ADMIN_STEP_UP_SECONDS`, all from Identity's `LoginAssurance`). All three extend SharedKernel's `DenyByDefaultVoter`. `UI\SendAdminToTwoStepProof` turns a refused `ADMIN_AREA` of such an Admin into a redirect, through Identity's `TwoStepProofPages`: to the setup page while two-step login is off, else to "Confirm it's you"; anyone else keeps the 403. The demo seed step `Infrastructure\Demo\SeedDemoOrganizations` creates Acme Foods, its teams and Beta Bakery through these commands. It may use the Api of Identity.
