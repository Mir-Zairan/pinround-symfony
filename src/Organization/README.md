# Organization

Organizations, teams, members, roles, invitations and settings such as ping limits and AI policy. It owns the tables `org_organization`, `org_membership`, `org_team`, `org_team_member`, `org_invitation` and `org_settings`. Its Api is `MembershipQueries`, `TeamQueries` and `OrgSettings`, and its events in `Api\Event` (`MemberJoined`, `OrgRolesChanged`, `TeamCreated`, `TeamRoleChanged`, all `OrganizationEvent`), which go through the outbox to `async_notify`. `MembershipQueries::rolesOf` gives one user's `Roles` in an organization (`isAdmin`, `isManager`, `isLeadOf`, `isMemberOf` and `isViewerOf` for exactly that team role, `isInTeam` for any, `teamIds`; `Roles::none()` without a membership) and `teamsOf` that organization's team ids; `DbalMembershipQueries` reads both under row-level security with no cache, so they need an open transaction under that organization as tenant and find nothing otherwise. Its commands in `Application` (`CreateOrganization`, `AddMember`, `SetOrgRoles`, `CreateTeam`, `SetTeamRole`) write in the caller's transaction and publish their events through `OrganizationEvents` (`Infrastructure\Messenger\MessengerOrganizationEvents`). SetOrgRoles locks the organization's admins and SetTeamRole the team before changing anything, so concurrent changes keep an admin and one lead. Built so far in `UI`: `EnterChosenOrganization` sets each web request's tenant from the organization chosen in the session, checked against `MembershipQueries::organizationsOf` (`resolve_user_orgs`), and `/org/choose` (`OrganizationChoiceController`, checked by `OrganizationMemberVoter`) lets a user choose or switch. The demo seed step `Infrastructure\Demo\SeedDemoOrganizations` creates Acme Foods, its teams and Beta Bakery through these commands. It may use the Api of Identity.
