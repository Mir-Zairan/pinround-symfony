# Audit

The activity log: who did what, when, with the old and new value. It is append-only. It owns the tables `aud_event` (P00.T7) and `aud_export` (P11). Its Api is `AuditLog::record(AuditEntry)` (an entry may carry the time of the action, `occurredAt`; else it is recorded at now), with `ActorKind` and `AuditEntryForAnotherTenantRefused`; `Infrastructure\DbalAuditLog` implements it. `Infrastructure\Health\NextAuditPartitionExists` tells `/health/ready` whether next month's partition exists. `Application\RecordOrganizationAuditEntry` records each Organization event once (`member.joined`, `member.invited` with the invitation as target and no data, `org_roles.changed`, `team.created`, `team_role.changed`, `settings.changed` with the organization as target and the setting's path, `from` and `to` (the provider key is recorded only as from null to "changed", never the key), at the event's time, with exactly the data keys of its `DATA_KEYS` allow-list); `config/services.yaml` tags it as an `event.bus` handler. `Application\RecordIdentityAuditEntry` records Identity's token events the same way: `api_token.issued` (data `scopes` and `expires_at`) and `api_token.revoked` (no data), with the token as target and never its text, hash, prefix or name. Both run their data through `Api\AuditDataAllowList::requireExactKeys`, which is in the Api so other modules that call `AuditLog` run the same check. It may use the Api of SharedKernel and the events of every module.
