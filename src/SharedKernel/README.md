# SharedKernel

The small set of types every module shares: ids, `Clock`, `TenantContext`, the `DomainEvent` base, `Result`/`Problem`, `DenyByDefaultVoter` (`UI\Voter`), the base that new voters on a subject extend (the two voters whose subject is null keep Symfony's `Voter`: Organization's `OrganizationMemberVoter` for `ORGANIZATION_CHOOSE` and Identity's `OwnAccountVoter` for `ACCOUNT_EDIT_OWN`; `AdminAreaVoter` extends it, with the request's `OrganizationId` as subject), and `OnceOnlyHandling` with `MessageIdStamp` and `MessageBeingHandled` for idempotent async handlers, and `Transactions` (`Application`, implemented by `Infrastructure/Doctrine/DoctrineTransactions`), which gives an action that runs without the request transaction one of its own under the request's tenant (Organization's People page invite and Ticketing's and Workflow's Team page actions; no module may use another's Application), and `RequiresRecentAuth` (`UI`), the attribute that marks a sensitive controller action; Identity enforces it ("Confirm it's you"), and it is here because most modules that will mark sensitive actions may not see Identity's Api, while every module may see SharedKernel, and `RelativeTime` (`UI`), the "now", "5 min ago", "3 h ago", "2 Nov" wording that Ticketing's What happened and tickets list and Conversation's thread print, whose UIs may not see each other, and `ReadinessCheck` (`Infrastructure/Health`) with the platform checks of `/health/ready`, and `DemoSeedStep` (`Infrastructure/Console`): one part of the demo data that `app:demo:seed` runs, in dev and test only. The module that owns the tables implements it, autoconfiguration tags it, and `#[AsTaggedItem(priority: …)]` sets the order. It is here, though only Identity and, from P01.T3, Organization use it, because the seed command must not import modules (the same reason as `ReadinessCheck`). `FieldEncryption` (`Application`, with `UndecryptableField`) and its libsodium implementation `SodiumFieldEncryption` (`Infrastructure/Encryption`) encrypt secrets stored in the database (ADR-0027): Identity's MFA seeds now, and later Integration's Jira and webhook secrets and the OIDC client secrets. `CitextType` and `TextArrayType` (`Infrastructure/Doctrine`) map PostgreSQL `citext` and `text[]` columns (Doctrine types `citext`, `text_array`); they are here because Doctrine registers a type once for the whole app, so a type cannot belong to one module. SharedKernel owns one table, `processed_message`, the record of which handler ran its effect for which message. `TicketTurnSnapshot` (`Domain`) is one ticket's turn facts, which Ticketing's `TicketTurnQueries` returns and Insight's `TurnProjector::refreshFrom` takes; only two modules need it, but both name it in their Api, which may see SharedKernel only. Its `peopleOnTheTicket()` (assignee, reporter, reviewer, tester and team lead, each once) is the one list of whom a question may ask: Ticketing's `LockedTicketPauses` checks it and Conversation's thread offers it as the composer's person chips. It has no Api interfaces of its own, because other modules use its types directly. It depends on no other module. Keep it tiny: a type joins only when three or more modules need it.
