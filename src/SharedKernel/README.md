# SharedKernel

The small set of types every module shares: ids, `Clock`, `TenantContext`, the `DomainEvent` base, `Result`/`Problem`, `DenyByDefaultVoter` (`UI\Voter`), the base that new voters on a subject extend (the two voters whose subject is null keep Symfony's `Voter`: Organization's `OrganizationMemberVoter` for `ORGANIZATION_CHOOSE` and Identity's `OwnAccountVoter` for `ACCOUNT_EDIT_OWN`; `AdminAreaVoter` extends it, with the request's `OrganizationId` as subject), and `OnceOnlyHandling` with `MessageIdStamp` and `MessageBeingHandled` for idempotent async handlers, and `ReadinessCheck` (`Infrastructure/Health`) with the platform checks of `/health/ready`, and `DemoSeedStep` (`Infrastructure/Console`): one part of the demo data that `app:demo:seed` runs, in dev and test only. The module that owns the tables implements it, autoconfiguration tags it, and `#[AsTaggedItem(priority: …)]` sets the order. It is here, though only Identity and, from P01.T3, Organization use it, because the seed command must not import modules (the same reason as `ReadinessCheck`). `CitextType` (`Infrastructure/Doctrine`) maps PostgreSQL `citext` columns; it is here because Doctrine registers a type once for the whole app, so it cannot belong to one module. SharedKernel owns one table, `processed_message`, the record of which handler ran its effect for which message. It has no Api interfaces of its own, because other modules use its types directly. It depends on no other module. Keep it tiny: a type joins only when three or more modules need it.

See the [module catalogue](../../docs/02-architecture/modules.md#sharedkernel).
